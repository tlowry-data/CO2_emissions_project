# Project Overview: Data Literacy Field Notes

## The objective

**The scenario:** A climate-and-energy nonprofit needs to decide where to
direct community-protection and climate-support efforts, and has just
received a new country-level energy and emissions dataset to help with
that — but nobody has actually opened the file yet. Before anyone can trust
a real decision built on top of it, you need real answers to:

- What does each column actually hold, and what data type is it?
- Is this dataset structured or unstructured?
- Is there anything about the data — missing values, suspicious rows — that
  should make someone cautious before using it to decide which communities
  need support?
- What's one specific question you'd ask the data's source before trusting
  it enough to act on?
- What's something about energy and emissions you're personally curious to
  explore in this data?

Set up your personal data-analytics development environment, then answer
all of this — plus a short AI-literacy reflection — in
**[`starter/field_notes.md`](starter/field_notes.md)**, "Data Literacy
Field Notes," inspecting the real dataset **using terminal commands only —
no Python code**, that starts in Module 1. Push it all plus a README to a
new **public GitHub repository** with at least two well-messaged commits.

## Why it matters

This is the very first project of the program — it isn't testing deep data
skills yet, and there's **no Python code** in it (that starts in Module 1).
It's testing whether you can set up a real development workflow (terminal,
git, GitHub) and look at unfamiliar data carefully and honestly — exactly
what the nonprofit in the scenario above needs before it can trust any
decision built on this data — both habits everything else in this program
builds on. Every later module assumes you can already do this without
being walked through it again.

## Deliverables at a glance

- `README.md` updated with the scenario, the questions you set out to

  data-quality question.

## Skills you'll practice

- **Programming fundamentals** — reasoning about variables, data types, and
  data structures (in your own words, not in Python code — that starts in
  Module 1).
- **Data literacy** — inspecting an unfamiliar dataset and describing it
  accurately.
- **Git & version control** — real, incremental commit history.
- **AI literacy** — distinguishing a verified fact from an unverified AI
  claim.
- **Curiosity** — asking a real, specific question you want to explore in
  data.
- **Critical thinking** — questioning a dataset's collection process, not
  just its surface.
- **Terminal / command line** — the main hands-on skill this project tests.
  You'll inspect real data entirely from the command line (`head`, `cut`,
  `grep`, `wc`, `sort`) — no Python code required or expected yet.
